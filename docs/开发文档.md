# ClipLink 开发文档

> 版本：1.1
> 日期：2026-09-17
> 定位：通过 ZeroTier，在两台 Windows 电脑之间双向同步纯文字剪贴板。
> 说明：已按便携化产品定义（单文件 cliplink.exe、免安装、不自动修改防火墙）与 V2.0 优化文档对齐更新。

## 1. 产品目标

ClipLink 是一个简洁、轻量的 Windows 托盘工具。两台电脑加入同一个 ZeroTier 网络并运行 ClipLink 后，输入对方的 ZeroTier IPv4 地址连接，即可自动双向同步剪贴板文字。

### 核心原则

- 简单：无账号、无云服务器、无复杂网络设置。
- 实用：只解决两台电脑之间的文字剪贴板同步。
- 安全：通过 ZeroTier 网络隔离，只能与同一网络内的设备通信。
- 轻量：关闭窗口后常驻托盘。
- 稳定：自动重连、消息去重、不形成回传循环。

### 第一版包含

1. 自动识别并显示本机 ZeroTier IPv4。
2. 输入对方 IP 并连接。
3. 双向同步纯文字。
4. 防止内容重复回传。
5. 断线自动重连。
6. 暂停和恢复同步。
7. 清晰的连接、同步和错误提示。
8. 系统托盘。
9. 可选开机启动。
10. 保存对方设备和设置。
11. 便携交付：单个 cliplink.exe，双击直接运行，无需安装器。

### 第一版不包含

- 图片、文件或富文本格式同步。
- 剪贴板历史正文。
- 多设备同步。
- 手机端、云账号或公网中继。

## 2. 用户流程

### 首次使用

1. 两台电脑加入同一个 ZeroTier 网络。
2. 把 cliplink.exe 分别复制到两台电脑并双击运行。
3. 两边自动显示自己的 ZeroTier IP。
4. 在电脑 A 输入电脑 B 的 IP，点击“连接”。
5. 双方完成 hello 握手后显示绿色“已连接”。
6. 任意一边复制文字，另一边剪贴板自动更新。

### 后续启动

1. 读取已保存的对方 IP。
2. 自动尝试连接上次设备。
3. 对方未启动时进入自动重连。
4. 连接恢复后只同步新内容，不补发断线期间的旧内容。

### 暂停同步

暂停后保持连接，但停止读取、发送和写入剪贴板。恢复后只处理新复制的内容，暂停期间的内容不补发。

### 状态规范

- 绿色：连接和同步正常。
- 黄色：连接中或重连中。
- 红色：连接或程序错误。
- 灰色：未连接、已暂停或未发现 ZeroTier。

必须提供的状态文字：

- 正在检测 ZeroTier 网络……
- 未发现 ZeroTier IP。
- 等待输入对方 IP。
- 正在连接对方……
- 已连接，剪贴板同步已开启。
- 已暂停同步。
- 连接已中断，正在重试……
- 无法连接，请确认对方程序已经启动。

### 系统托盘

关闭窗口时只隐藏，不退出。托盘菜单包含：当前状态、打开主界面、暂停/恢复、重新连接、开机启动和退出。只有点击“退出 ClipLink”才结束进程。

### 最小化状态呼吸灯

用户主动最小化主窗口后，显示一个小型悬浮呼吸灯（替换任务栏最小化形态）；绿色=Connected，黄色=Connecting/Reconnecting，红色=Error，灰色=Offline/Paused。呼吸灯随连接状态实时换色，点击呼吸灯恢复并聚焦主窗口。开机静默启动（--minimized）不显示呼吸灯。最小化接管只在主窗口“已正式展示”后生效（正常启动做好一次可见确认，或经托盘/呼吸灯恢复主窗口时解锁），避免启动阶段窗口布局瞬态被误判成用户最小化。

## 4. 技术方案

### 技术栈

- 桌面框架：Tauri 2。
- 前端：Vue 3、TypeScript、Vite。
- 核心：Rust。
- 异步运行时：Tokio。
- 网络：TCP 长连接。
- 消息：4 字节长度前缀加 JSON。
- 剪贴板：`arboard`，仅使用文字接口。
- 序列化：`serde`、`serde_json`。
- 摘要：SHA-256（仅用于本机剪贴板内容变化判断，见第 10 节）。
- 配置：应用数据目录中的 JSON。
- 日志：`tracing`，禁止记录剪贴板正文。

### 网络参数

- 默认端口：`45888/TCP`。
- 连接目标：`对方 ZeroTier IP:45888`。
- 监听地址：优先绑定本机 ZeroTier IP，不监听全部网卡。
- 单条消息上限：1 MiB。
- 连接超时：5 秒。

### 后台任务

1. `network_listener`：监听对方连接。
2. `connection_manager`：主动连接、状态和重连。
3. `clipboard_worker`：单线程访问 Windows 剪贴板。
4. `heartbeat_worker`：发送心跳、判断失联。
5. `config_worker`：保存配置和设备信息。

剪贴板访问集中到一个工作线程，避免并发访问 Windows 剪贴板。

## 7. ZeroTier IP 检测

1. 枚举 Windows 网络适配器。
2. 查找名称或描述包含 `ZeroTier` 的网卡。
3. 读取该网卡的 IPv4 地址。
4. 排除回环地址、链路本地地址和 `0.0.0.0`。
5. 找到有效地址后更新状态并通知界面。
6. 每 10 秒复查；连接失败或网卡变化时立即复查。

不能只根据 `10.x.x.x` 等网段判断，因为普通局域网也可能使用私有地址。必须结合网卡名称或描述。

未检测到时显示：“未发现 ZeroTier IP，请确认 ZeroTier 已启动，并且本机已经加入并获准访问网络。”

## 8. 通信协议

### 消息边界

```text
4 字节无符号大端整数：JSON 字节长度
N 字节：UTF-8 JSON
```

接收端先检查长度，再分配缓冲区和解析 JSON。

### 公共结构

```json
{
  "version": 1,
  "type": "clipboard_update",
  "message_id": "UUID",
  "timestamp": 1789550000000,
  "device_id": "发送方设备 ID",
  "payload": {}
}
```

### 消息类型

- `hello`：交换版本和设备信息。
- `clipboard_update`：纯文字更新。
- `ping` / `pong`：心跳。
- `disconnect`：正常断开。
- `error`：协议错误。

暂停/恢复属于本地状态（Connected ↔ Paused），不是网络协议消息。

协议版本固定为 `1`。版本不兼容时停止同步并提示更新。

## 9. 安全模型（无配对）

本版本**不做配对、不做消息认证**（设计取舍，2026-09-16 经确认从需求中移除）。

- 信任边界是 ZeroTier 网络本身：只有加入同一 ZeroTier 网络、且知道对方 ZeroTier IP 的设备才能建立连接；应用只监听本机 ZeroTier IP（不监听 0.0.0.0），并从网络层拒绝回环/本机/组播等非法目标。
- 连接建立即信任：hello 交换（校验版本、设备 ID 为 UUID、设备名非空、对方不等于本机）成功后直接进入已连接，业务消息不带认证。
- `hello` 中的本机密钥（device_secret）仅在本机生成并保存，不上网络、不参与通信。
- 每台设备用稳定的 `device_id` 唯一标识，用于对端展示与防自连。

### 保留的协议含义

经用户确认（2026-09-16），第一阶段放弃“首次配对确认”与“每次连接认证”，换取“填 IP 即连”的极简体验。当前版本不包含六位确认码、共享密钥、HMAC、挑战应答或解除配对。

## 10. 剪贴板同步逻辑

### 本地监听

1. 每 300 毫秒读取一次纯文字。
2. 读取失败时跳过本轮并稍后重试。
3. 对文字计算 SHA-256。
4. 与上次观察到的哈希比较。
5. 未变化则不处理。
6. 如果是刚写入的远程内容，则不发送。
7. 否则发送 `clipboard_update`。

### 收到远程文字

1. 验证消息大小和结构。
2. 检查消息 ID 是否已经处理。
3. 验证正文哈希。
4. 记录远程写入哈希。
5. 将纯文字写入剪贴板。
6. 更新本地观察哈希。
7. 通知界面更新“最近同步”。

### 防循环

同时使用三层保护：消息 ID 去重、短时间内容哈希去重、远程写入标记。最近消息 ID 保留 100 条即可，应用重启后无需保留。

### 内容规则

- 只同步纯文字。
- 空字符串不发送。
- 中文、英文、Emoji、多行文字原样处理。
- 单条上限 1 MiB。
- 不尝试识别密码。
- 不将正文写入配置或日志。

## 11. 连接与重连

### 建立连接

1. 校验输入是否为 IPv4。
2. 禁止连接自己的 ZeroTier IP。
3. 使用 5 秒连接超时。
4. TCP 建立后发送 `hello` 并等待对方 `hello`（校验版本与设备信息）。
5. 成功后进入 `Connected`。

### 心跳

- 每 10 秒发送一次 `ping`。
- 连续 3 次没有 `pong` 则判定失联。
- 心跳不改变“最近同步”时间。
- 心跳不仅用于失联判断，也用于 RTT 测量：收到匹配的 `pong` 时，用本机记录的该 ping 发送时间计算往返毫秒数，并以 `network-latency-changed` 事件推送给界面。
- UI 对方设备状态卡（PeerStatusCard）在已连接/已暂停时显示最近一次有效 RTT，例如“延迟 18 ms”；尚未取得有效 RTT 时不显示延迟。
- RTT 只是当前 TCP 心跳往返时间，不是 ZeroTier 链路质量评分。

### 重连间隔

```text
2 秒 → 5 秒 → 10 秒 → 20 秒 → 30 秒
```

之后每 30 秒尝试一次，连接成功后重置。用户主动断开时不自动重连。

双方同时主动连接时，各自先占用本地单连接槽位，对方的入站连接因槽位 busy 被立即拒绝，因此不会出现“两条连接都握手成功后再比较 device_id”的状态。连接失败后依靠自动重连（退避叠加由稳定的 `device_id` 派生的固定抖动 0~1500ms）错峰重试，最终收敛为一个同步通道。实现不使用 ConflictLost / device_id winner 分支；`device_id` 仍用于稳定身份标识与抖动计算。

## 14. Windows 防火墙（正式策略）

ClipLink 不主动修改 Windows 防火墙。

- 不执行 firewall.ps1，不创建、不删除任何入站规则。
- 不请求 UAC。
- 优先绑定 ZeroTier IP，不监听 `0.0.0.0`；ZeroTier IP 改变后重新绑定。
- 如果 Windows 首次运行时弹出系统网络访问提示，由用户按自己的网络策略决定。
- 无“一键放行”功能。

### 阶段 6：单机剪贴板监听

1. 创建剪贴板工作线程。
2. 每 300 毫秒读取纯文字。

4. 读取失败时重试。

### 阶段 7：双向同步

1. 本地变化时发送剪贴板消息。
2. 接收端验证后写入剪贴板。
3. 增加消息 ID 去重。
4. 增加哈希去重和远程写入标记。
5. 更新最近同步状态。
6. 测试双方快速交替复制。

完成标准：A 到 B、B 到 A 均正常；每次复制只同步一次；不会无限回传；中文、Emoji 和多行文字不变。

### 阶段 8：自动重连和冲突处理

1. 实现退避重连。
2. 对方重启后自动恢复。
3. 网络断开后自动恢复。
4. 处理双方同时连接。
5. 用户主动断开时停止重连。

完成标准：连接状态准确；网络恢复后自动连接；始终只有一个通道；旧内容不补发。

### 阶段 9：托盘和开机启动

1. 创建系统托盘和菜单。
2. 拦截关闭窗口并隐藏。
3. 双击托盘打开窗口。
4. 开机启动：用系统自带 reg.exe 写 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`，值为 `"<exe>" --minimized`，无需管理员权限。
5. 开机启动时默认静默到托盘。

完成标准：窗口关闭后同步继续；托盘可暂停、恢复、打开和退出；开机启动设置持久化。

### 阶段 10：便携化交付（需求变更：不用安装包和防火墙）

用户确认在自有可信网络中使用，更新需求：取消"安装包和防火墙"原方案，改为免安装便携交付。

1. 配置名称（productName/version）、正式应用图标（exe/托盘/窗口，`tauri icon` 全量生成）。
2. 交付物为**单个可双击运行的 `cliplink.exe`**（`tauri build --no-bundle`，release 单文件、内嵌前端资源、无安装/UAC），复制到其他电脑也能直接运行。
3. 不生成安装包、不写防火墙入站规则、不改变任何系统安全设置；应用自身读取本机身份/配置于 app_data 目录自动创建，不依赖安装过程。

完成标准：`tauri build --no-bundle` 产出单文件 exe；双击即运行（含 WebView2 环境的普通 Windows 10/11 电脑）；拷到其他电脑双击同样运行。

### 阶段 11：测试和发布

单元测试：IP 校验、消息编解码、哈希、去重、重连退避和连接冲突收敛。

集成测试：双向同步、大文本拒绝、断线重连和同时连接。

手工测试：中文、英文、Emoji、多行、快速复制、休眠唤醒、锁屏解锁、ZeroTier 断开恢复、同时启动/同时连接、暂停/恢复、托盘、开机启动、便携复制到另一台 Windows 电脑运行。

发布标准：连续运行 24 小时无崩溃；同步 1,000 次无循环；网络恢复测试 20 次；日志无正文；`tauri build --no-bundle` 单文件 cliplink.exe 拷到另一台 Windows 电脑双击可直接运行。

## 16. 推荐开发顺序

1. 项目和静态界面。
2. ZeroTier IP 检测。
3. 配置与身份。
4. TCP 和心跳。
5. 单机剪贴板监听。
6. 双机同步。
7. 防循环。
8. 自动重连。
9. 托盘和开机启动。
10. 便携化交付（tauri build --no-bundle，去掉安装器和防火墙）。
11. 完整测试。

先保证核心稳定，不提前开发动画、历史、多设备和文件传输。

## 17. 里程碑

- M1 界面原型：展示 IP 和状态。
- M2 网络打通：两台电脑通过 ZeroTier 连接并交换设备名。
- M3 核心可用：双向文字同步稳定且不循环。
- M4 桌面体验：重连、托盘、暂停和开机启动可用。
- M5 便携发布：cliplink.exe 单文件双机运行与完整测试通过。

## 20. 最终定义

ClipLink 第一版只做一件事：两台已加入同一 ZeroTier 网络的 Windows 电脑，通过输入对方 IP 直接连接，简单、稳定、安全地双向同步纯文字剪贴板。

任何不能直接增强这条主流程的功能，都不进入第一版。
